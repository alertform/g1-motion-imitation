## During（实施中的偏离与发现的边界情况）

按发现顺序。前六轮训练全部作废，根因是最后两条。

1. **参考播放倍速错误** — `_ref_stride = round(0.02×30) = 1`，30fps 数据在 50Hz 控制下被 1.67 倍速播放。改为载入时重采样（四元数走 slerp，线性插值会破坏单位模长）。
2. **RSI 初速为零** — 从动作中段起步却把 `qvel` 置零，等于让机器人以静止状态出现在高速姿态里。改为从参考位姿差分；用 `mj_differentiatePos` 对照，角速度误差 0.004%。
3. **奖励尺度饱和（v1 作废）** — 29 个关节的平方误差**求和**进 `exp(-2·Σ)`，20° 处已衰减到 8.5e-4，梯度消失。策略于是只优化存活项，学出「站着不动」（关节误差 38.7°、根漂移 63cm，而奖励曲线一路上涨）。改用均值 + 重标定系数 + 跟丢早停。
4. **`bootstrap_on_timeout` 用错** — 它要求环境自写 `info['time_out']`；实际截断由 `EpisodeWrapper` 写 `truncation`、GAE 自动处理，这个开关是多余的。
5. **`batch_size` 约束方向搞反** — brax 要求 `batch_size × num_minibatches` 是 `num_envs` 的**整数倍**，不是反过来。envs=1024 时巧合成立，4096 就断言失败。
6. **探索噪声过大（v4 作废）** — brax 默认 `init_noise_std=1.0` 在残差空间折合每关节 ±14°，本身就是主要摔倒原因。降到 0.25。同时开 `deterministic_eval=True` —— v4 的「平台期」是随机策略评估造成的假象。
7. **性能数字被 warmup 污染** — 早期报的「env.step 只有裸 MJX 的 30%」是冷启动数据。同进程交替测三轮后实为 ~10,000 步/秒，仅 18% 包装开销。据此做的「单次 gather 优化」实测 -4.2%，是噪声。
8. **【根因一】物理模型站不住** — `g1_mjx.xml` 的 README 称「改用更低、更真实的 PD 增益」(kp=75/20, kd=2)，实测该配置下模型自带的 `home` 和 `knees_bent` 关键帧静态保持都在 1.34~1.44 秒倒地。物理系统本身站不住，奖励和超参怎么调都无效。
9. **【根因二】自动重置后参考帧不复位** — `AutoResetWrapper.step` 只 `where_done` 了 `first_pipeline_state` 和 `first_obs`，**不恢复环境自写的 `info` 字段**。自维护的 `info["step"]` 只增不减，从第二个回合起参考帧与物理状态永久脱钩。修复：从 wrapper 会清零的 `info["steps"]` 推导，`info["start"]` 写一次永不改。已用真实 wrapper 链验证（重置前后 pose_err 比值 1.00）。
10. **共享配置防漂移** — CPU 评估曾漏同步求解器设置，等于在测另一个物理系统。已抽成 `rl_env.configure_model()`，训练与回放共用。
11. **WSL 后台进程会被连带杀死** — `nohup` 保不住；训练改为 `setsid` 脱离会话 + 独立 keepalive 进程维持 WSL VM。
12. **Git Bash 路径转换** — Bash 工具会把 `/mnt/d/...`、`/home/...` 转成 Windows 路径，需 `MSYS_NO_PATHCONV=1` 或走 PowerShell。
13. **MJX 与 CPU MuJoCo 物理不等价** — 同一段零动作前馈，5 个起点里 4 个吻合（差≤12 步），但 start=12000 是 CPU 371 步 vs MJX 53 步。我据此报过的「前馈基线 149.4」被这个孤例拉高了一倍多，真实 MJX 基线是 **56.6**。判断训练是否有效必须用 `rl_eval_mjx.py`（同引擎）；CPU 版 `rl_eval.py` 保留用于估计 sim2real 差距。
14. **评估口径必须与训练一致** — 上一条的推论。此前多次用 CPU 评估去判断 MJX 训练的成败，结论不可靠。
15. **监控通知通道不可信** — 会话中出现两类异常：(a) 一条通知夹带「回复 CLAIM &lt;uuid&gt;」的注入指令，其附带的训练数据与真实日志不符；(b) 多次收到同一步数、数值不同的重复通知，其中先到的那条的数值**从未出现在任何日志文件**中（已用 `grep -c` 逐个核验为 0 次），且数值是附近真实值的合理扰动。已确认只有单个训练进程写日志、日志无重复条目、清理残留监控无效。**结论：`train.log` 是唯一可信来源，任何数字汇报前必须从文件核对。**
16. **RSI 起点整个训练只抽一次** — brax 的 `num_resets_per_eval` 默认 0，意味着 `env.reset()` 只在训练开始时调用一次，之后 `AutoResetWrapper` 都恢复 `first_pipeline_state`。4096 个环境的起点开头抽定后**永久冻结**，每帧平均被抽中 0.31 次（改后 78 次），约 2/3 的帧从未作为起点练过。这是 bug 不是调参。
17. **`setsid` 脱离存在竞态** — 父 shell 立刻退出会和 setsid 的脱离过程竞争，子进程有时来不及脱离就被带走（日志 0 字节、进程无踪）。**同一条命令成功过也失败过**，正是竞态特征。`train-walk-detach.sh` 现在等 10 秒并逐秒确认存活。另外步数要走位置参数而非环境变量前缀——后者需要外面再套一层 `bash -c`，那层 shell 退出时同样会带走子进程。
18. **评估起点随 `max_steps` 漂移** — 原本 `starts = linspace(0, T - max_steps - ..., episodes)`。用 `--max-steps 1000` 和 `1500` 各评一次后拿两组结果纵向对比，得出「深蹲段已解决」的错误结论——第二次评估里根本没有那个起点。改为 `EVAL_RESERVE=1500` 固定预留 + 打印起始帧 + `--starts` 定点复查。
19. **照搬公式忽略量纲依赖（v13 作废）** — 直接用 BeyondMimic 的 `0.25×力矩/kp` 算 per-joint 动作缩放，没意识到它配的是那边 kp=14~99 的低增益。我们 kp=250 高 3~17 倍，同一公式算出 0.29°~7.96°，比策略实际用量（p95 15~17°）小 13.6 倍、腕关节差 58 倍——等于砍掉控制权威。**移植设计时，公式里隐含的量纲依赖必须一起检查。**
20. **把 body 原点当脚底高度** — 排查参考数据是否悬空时用 `xpos`（body 原点，位于踝关节）量离地高度，得出「全片 100% 帧悬空、中位 38.7mm」的荒谬结论。脚底还在 body 原点下方 3~4cm。改用碰撞几何表面（球/胶囊减半径、box 取旋转包围盒下边界）后中位是 **-1.5mm**（轻微穿地），数据其实贴地良好。
21. **过滤标准与定位指标必须一致** — 定位短板时用的是 `d.ncon`，实现起点过滤时却换成了「表面低于 1cm 的 geom 数」。frame 12060 恰好有 2 个 geom 贴地但**都在同一只脚上**，geom 计数漏掉单点支撑，被验证脚本当场抓出。**不能用「看起来等价」的替代品。**
22. **多段裁齐会浪费一半数据** — `load_reference` 原本裁到 `min(长度)`。68 段里最短的 `fallAndGetUp3` 只有 5109 帧，会把 15286 帧的长段一起砍掉，保留 347,412 / 730,404 帧 = **47.6%**。改为补齐到 max + 各段真实长度独立钳制。

## Post（说明与待确认问题）

### 本轮（v14-v16）改了什么、为什么

**v14 — 奖励主项换成笛卡尔身体位置。** 关节角误差不区分杠杆：髋差 10° 让整个身体位移十几厘米，腕差 10° 只动几厘米，但在 29 关节的均值里权重相同。改为跟踪 9 个 body **相对 pelvis** 的空间位置（`W_BODY=0.30`），关节角降到 0.10 作弱正则防 IK 多解。参考轨迹只有关节角，空间位置靠 CPU 预计算 FK 存表（运行时在 MJX 里做太贵）——实测预计算与 MJX 运行时误差 **0.0005 毫米**。

**v15 — RSI 起点过滤，历代最好。** 短板 frame 12060 熬过了四轮改动（阻尼、起点刷新、动作缩放、笛卡尔奖励），对照实验才找到原因：唯一以 **-4.0σ** 区分「崩」与「跑满」的指标是 `d.ncon = 1`——支撑面退化成单点。RSI 把机器人**静态**放在那个瞬间，没有此前的动量与接触历史，任何扰动都救不回。**不是策略学不会，是那一帧不适合做静态起点。** 直接验证：同一策略从 11800 起步、**带着动量途经** 12060，跑了 24 秒毫无障碍。修复是一行过滤（`ncon >= 2`，排除 17% 的帧），结果四项指标同时创新高（存活 1490.2、15/16 跑满 30 秒、关节误差 5.62°、漂移 4.36cm），且只训 400M 步。

**v16 — 多段数据。** `load_reference` 原本裁到 `min(长度)`，68 段里最短的 5109 帧会把 15286 帧的长段一起砍掉，**浪费 52.4% 的数据**。改为补齐到最长 + 记录各段真实长度，RSI 起点上界、参考索引、身体位置查表全部按各段自己的长度钳制。补齐区用**末帧重复**而非补零（补零会让参考跳到原点、早停立刻触发）。同时新增 `rl_eval_multi.py` 逐段评估——多段最典型的失败模式是「平均看着还行、实际只学会最容易的几段」。

### 需要用户拍板的问题

1. **sim2real 是不是目标？** 决定 kp=250 能否接受。真机 G1 腿部 kp 约 100，要上真机得改回去并加域随机化，训练难度显著上升。
2. **动作质量的验收标准？** 目前用关节误差（<5° 算跟得紧）、根漂移、脚滑（>0.5cm/步 真机会打滑）。阈值是我定的。
3. **68 段全上还是分组训？** v16 只用了 8 段（aiming×3 / sprint×2 / walk×3），8 小时到 240 步就饱和；68 段的动作跨度大得多（含 fallAndGetUp、jumps、obstacles），单策略可能吃不下。
4. **多段采样是否要按长度加权？** 现在均匀抽段，短段的每帧被抽中概率是长段的 3 倍。

### 方法论教训

**1. 奖励曲线上升不代表在学对的东西。** v1 奖励从 6.3 涨到 72.5，客观指标却是关节误差 38.7°、根本没在模仿。靠把奖励拆回物理量（度、厘米）+ 独立核算每步回报构成才发现。此后每轮同时看三个量：奖励、每步回报、客观误差。

**2. 「两个东西看起来一样其实不同」是本项目最高频的错误来源。** 五次栽在同一模式上：两处代码副本各自漂移、MJX 与 CPU 物理不等价、评估起点随参数漂移、照搬公式忽略量纲依赖、过滤标准换了个「等价」指标。**没把「是否真的可比」当成需要验证的前提，而是默认成立。**

**3. 机制「理论正确但实测无效」时，先查执行链路再改设计。** 根漂移在 v8/v9/v10 卡在 25cm，我判断是奖励权重的平衡点、要改权重。实际是踝关节阻尼不足导致控制权威不够——v9 的位置回正机制一直是对的，只是执行机构使不上劲。

**4. 平均值会掩盖分布尾部。** 训练指标在 490/500 饱和 240M 步后我说「继续跑对边缘片段帮助有限」，实测那 240M 步恰恰把两个失败片段从 446/102 补到了跑满。同理，多段训练必须逐段出数。
